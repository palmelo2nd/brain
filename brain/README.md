## 1. タスク管理タブ

タスク・ナレッジの親子関係を「親ID」1本で表現する中心画面。旧・繰返し／旧タスク整理／タスク実行／プロジェクト／勤務の5タブを統合したもので、フィルタ〜カレンダー〜1日タスク〜編集フォームまでを常時表示のまま、上部の表示切り替えで5つのビューを切り替える。DOM上のIDプレフィックスは `taskorg2-` / `calendar2-` / `dayedit2-`。

### 1.1 表示切り替え（カレンダー／ガントチャート／習慣／勤務歴／プロジェクト）

画面上部のサブタブで5ビューを切り替える。年月・選択日（`taskorg2CalendarYear`/`Month`、`selectedTaskorg2Date`）はカレンダー・ガントチャート・習慣（月表示）・勤務歴の間で共有される。

### 1.2 フィルタ

- 画面上部（および[1.13 タスク一覧](#113-タスク一覧)直上）の「フィルタ」を展開すると、タグ／ステータスの複数選択と、「その他フィルタ」（プロジェクト／繰返しテンプレート／繰返し実行タスクの表示ON/OFFチェックボックス）を表示する。上下2箇所は同じ状態を参照する複製なので、どちらを操作しても同期する。
- 「その他フィルタ」の下に、プロジェクト（複数選択）で選んだものを起点にPJ(1層)→PJ(2層)…と辿れるドリルダウン用プルダウンを配置し、階層を絞り込んで子孫タスクだけに絞り込める。
- 以降のカレンダー・ガントチャート・習慣・プロジェクトツリー・タスク一覧はすべてこのフィルタが適用された結果を対象にする。

### 1.3 カレンダービュー

月間グリッドに、その日の勤務区分（[1.6 勤務歴](#16-勤務歴)の例外設定があればそちらを優先）を背景色で反映しつつタスクを表示。日をクリックするとその日を選択し、下の[1.8 日別タイムライン](#18-日別タイムライン1日タスクdayplan)に反映する。

### 1.4 ガントチャートビュー

表示単位「日」「週」を切替可能。ステータス別配色（未着手／進行中／中断等／連絡待ち・報告待ち／完了）で日付列にマーカー表示し、日付列クリックでその日を選択、行クリックで編集対象に切り替える。

### 1.5 習慣（週／月／毎日）

繰返し親タスク（テンプレート）を、頻度設定に応じて視覚的に配置する表示専用ビュー（クリックで右の[編集フォーム](#111-編集フォームタイマー機能含む)に読み込む点は他ビューと同じ）。表示単位「週」「月」「毎日」をボタンで切り替える。

| 単位 | 対象・表示 |
|---|---|
| 週 | 「頻度（曜日）」を設定している親タスクを、月〜日の固定表（曜日名の一致のみで判定、日付非依存）に表示 |
| 月 | 「頻度（日）」または「頻度（月）」を設定している親タスクをカレンダーの該当日に表示。日＋月の両方設定＝月が一致する時だけ／日のみ＝毎月その日／月のみ＝日付を特定できないためカレンダー下の「日付指定なしタスク」に表示 |
| 毎日 | 「頻度（曜日）」または「頻度（日）」の選択肢がマスタ定義の全選択肢を満たしている（＝実質「毎日」指定）親タスクを表示。週・月タブ側ではこの分を除外する |

いずれの単位でも、頻度（月・日・曜日）がすべて未設定の親タスクは「頻度未指定タスク」として別枠に表示する。

### 1.6 勤務歴

出勤日・休日・有給・特別休暇などの勤務区分をカレンダー形式で管理する（旧「勤務タブ」をそのまま移植）。

- 年・月それぞれに `‹` `›` ボタンで移動。
- 月間グリッドに、既定の曜日パターン、または個別の例外設定があればそちらを優先して色分け表示。例外設定がある日は専用マークを表示。
- 月次サマリー：表示中の月について区分ごとの日数を集計表示。
- 月一括編集フォーム：1日1行のテーブルで種別（デフォルトのまま／出勤日／休日／有給／特別休暇）と備考を入力し、「月一括適用」ボタンでまとめて保存する（種別が「デフォルトのまま」の行は例外設定から除外＝既定の曜日パターンに戻る）。
- ここで設定した勤務区分は、[1.3 カレンダービュー](#13-カレンダービュー)・[1.4 ガントチャートビュー](#14-ガントチャートビュー)（日単位）の非稼働日表示にも反映される。

### 1.7 プロジェクト（ツリー表示）

「親ID」で表現された階層構造全体を、折りたたみ可能なインデント付きツリーで一覧表示する（旧・独立した「プロジェクトタブ」の階層ブラウザ／階層整理は廃止され、このツリー1つに統合されている）。

- 各行はステータス別（完了→報告待ち→連絡待ち→中断→進行中→未着手→未設定の順）にグループ化されて並び、直属の子だけでなく孫以降も含めた子孫総数をタイトル横に表示する。既定では「ステータス=完了」の親だけを折りたたんでおき、手動で開閉した状態は行ごとに記憶する。
- 行クリックで右の[編集フォーム](#111-編集フォームタイマー機能含む)に読み込む。行頭のチェックボックスは複数選択用（本章末尾のPJ一括編集参照）。
- **PJ一括編集**：ツリーに限らず、[1.9](#19-未設定対応中対応待ち属性未設定タスクなどの一覧)・[1.10](#110-繰返しタスク)・[1.13](#113-タスク一覧)のチェックボックス付き一覧を横断してチェックした全タスクへ、ここで選んだPJ(n層)階層プルダウンの親IDだけを一括適用するボタン。「＋ 新規PJを追加」でその場に新規プロジェクトを作成して選ぶこともできる。タイトル・ステータスなど他の属性には一切触れない。

### 1.8 日別タイムライン・1日タスク（DAYPLAN）

- 0:00〜24:00を縦軸にしたタイムラインに、選択日の「開始予定・終了予定に時刻が入力されているタスク」をブロック表示する。横軸は常に**固定4列**（縦の点線で区切りを表示）で、列1＝開始予定・終了予定が既に時刻まで決まっている「拘束される予定」の定位置、列2〜4＝時間未定タスクを手動またはドラッグで置いていく作業枠。ブロックには常に細い黒枠が付き、選択中のブロックは太い黒枠になる。チップにはタイトルのみ表示する（時刻は表示位置で分かるため非表示。対応中タスク一覧などのチップでは引き続き時刻を表示する）。
- 未確定タスクや、1日タスクのブロックとして参照済みのタスクは通常枠に出さず、[1.9](#19-未設定対応中対応待ち属性未設定タスクなどの一覧)側に振り分ける。
- **ドラッグ操作**：縦方向で時刻を変更（15分単位にスナップ）、横方向で列を変更できる。端のハンドルをドラッグするとリサイズ（所要時間の変更のみ、列は変わらない）。列2〜4で他のブロックと時間が重なった場合は、衝突した既存ブロックの直後へ自動的にずらして配置し、その結果さらに後続のブロックと重なればそれも連鎖的に押し出して解消する。押し出しの結果どれかが24:00を超える場合は、ドロップ操作自体をキャンセルする（列1は重なりを気にせずそのまま配置する）。まだ1日タスクに追加していないタスクを列方向にドラッグすると、その時点で1日タスクへ追加（昇格）される。
- **1日タスク（DAYPLAN）**：選択日ごとに1件、その日のスケジュールをテキストで管理する特殊行（詳細仕様は[添付E](#e-1日タスクdayplanの共通仕様)）。未作成の日は「1日タスクを作成」ボタンで新規作成し、その日既に時刻指定済みの既存タスクを自動的に取り込んで列1のブロックにする（既定は「09:00-09:30 メールチェック、予定整理」を含む）。「保存」でテキスト内容を反映、「1日タスクを削除」でその日の1日タスク自体を削除。
- [1.9](#19-未設定対応中対応待ち属性未設定タスクなどの一覧)などのチップの＋ボタンで1日タスクへ追加する際、開始予定・終了予定が既に決まっているタスクは列1へ、時間未定のタスクは列4へ9:00起点30分刻みで次の空き枠を自動的に割り当てる（重なりの押し出しは行わず、空いている枠を探すだけ）。
- タブを開いた時点では常に「今日」が選択された状態になる。

### 1.9 未設定／対応中／対応待ち／属性未設定タスクなどの一覧

いずれも現在のフィルタ・カテゴリ適用後の一覧をチップ形式で表示し、クリックで編集対象に選択できる（既定は折りたたみ）。チップ左のチェックボックスは[PJ一括編集](#17-プロジェクトツリー表示)の複数選択対象、チップ左端には優先度ドット（高＝赤／中＝黄／低＝緑）を表示する。「1日タスクに追加済み」一覧を除くすべてのチップに、[1.8](#18-日別タイムライン1日タスクdayplan)の1日タスクへ追加する＋ボタンを配置しており、状態を問わずどのタスクも1日タスクに追加できる。

| 折りたたみ項目 | 内容 |
|---|---|
| 対応中タスク（期間内） | 選択日について、未設定（時間帯未定）タスクと、1日タスクに追加済み（参照済み）のタスクを分けて表示。期間＝開始予定〜終了予定 |
| 対応待ちタスク（期間外） | 連絡待ち／報告待ち／中断のうち、開始予定・終了予定がともに入力済みで、今日がその期間内ではないタスク |
| 属性未設定タスク | カテゴリ／ステータス／優先度／プロジェクト（親ID未設定）／日付（開始予定・終了予定のいずれかに日付部分が無い＝空欄または時刻のみ入力）のいずれかが未入力のタスクを領域別に表示（重複表示あり） |

### 1.10 繰返しタスク

繰返し親タスク（テンプレート）と、そこから生成された実行タスク（子タスク）を左右に分けて操作するExpander（既定は折りたたみ、パフォーマンスのため開いている時だけ再描画する）。[1.5 習慣](#15-習慣週月毎日)が「頻度に沿った視覚的な配置」に特化しているのに対し、こちらは「実行タスクの生成・選択」に特化している。

- **テンプレート（左）**：登録済みの繰返し親タスクをチップで一覧。頻度が今日に該当するものを赤枠で強調し、子タスクが多いものほど上に表示。チップ右の「＋」ボタンで、「基準日」入力欄の日付を基準に実行タスクを「進行中」ステータスで生成する（既に生成済みの日付分は生成しない）。
- **実行タスク（右）**：選択中テンプレートの子タスクを基準日の新しい順にチップで一覧。チェックボックスで複数選択できる（[PJ一括編集](#17-プロジェクトツリー表示)対象）。
- **実績グラフ**：選択中テンプレートの子タスク実績（完了日 or 作成日時 × 実績時間）を折れ線グラフで可視化（Chart.js使用）。既定は非表示で「実績グラフ」ボタンで表示切り替え。

### 1.11 編集フォーム（タイマー機能含む）

親タスク・子タスク・通常タスクいずれを選択した場合も同じフォームを使うが、一部の項目は選択内容に応じて表示が切り替わる。「新規登録」ボタンでフォームをリセットし新規登録モードへ（この場合のみ日付を空欄のままにする。それ以外はカレンダー等で選択中の日付を初期値にする）。

| 項目 | 内容 |
|---|---|
| ID / タイトル / 内容 | 基本情報 |
| カテゴリ・タグ | マスタ選択式 |
| 親（プロジェクト） | ID・タイトルで検索して任意の階層に紐付けるPJ(n層)階層プルダウン。「＋ 新規PJを追加」でその場に新規プロジェクトを作成可能。「親を解除」で親なしに戻せる |
| ステータス | ステータス選択。「完了」に変更すると、完了日が未入力の場合のみ自動的に本日にする（既に入力済みなら上書きしない） |
| 優先度 / 見積時間（分） / 実績時間（分、読取専用） | 通常のタスク属性 |
| 開始予定・終了予定・完了日 | 日付＋時刻（時／分）。開始予定の日付を入力すると終了予定の日付に同じ日付を自動セット。開始予定の時（時間）を入力すると、開始予定の分を0に、終了予定を「時+1・分0」に自動セット（日付をまたぐかどうかは判定しない、いずれも手動修正可）。「開始/終了リセット」ボタンで開始予定・終了予定（日付・時・分）をまとめて空欄に戻せる。「開始/終了に反映」ボタンで完了日の値を、空欄になっている方だけに代入できる |
| 繰り返し（チェックボックス） | オンにすると、このタスクを繰返しタスクの親として扱い、頻度（月・日・曜日）の入力欄と、下記「実行タスクテンプレート」欄を表示する（OFF時は備考欄を表示） |
| 実行タスクテンプレート | **繰り返しON時のみ表示**。1回の生成で複数の実行タスクを作成できるようテンプレートを複数登録可能（開始予定・終了予定は基準日からのオフセット日数、タイトル接尾辞、内容を行ごとに指定）。実体は備考欄にJSON文字列として保存される |
| 備考 | **繰り返しOFF時のみ表示** |
| タイマー | **ステータスが「進行中」の既存タスクを選択中のみ表示**。`▷`／`■`でタイマー開始・停止（打刻はタイムスタンプログに追記、実行中は開始ボタンを無効化）。累計時間はライブ更新、「補正時間」欄で分単位の加減算が可能。タイムスタンプログはテキストエリアで直接編集可 |

- **操作ボタン**：「新規」（登録モードへリセット）／「適用」（変更を保存）／「削除」（選択中タスクを削除）。
- **グループに適用**（繰返し基準日を持つ子タスク選択時のみ表示）：開始予定・終了予定の変更差分（両方変更時は開始予定側優先）を日数差分として算出し、同じ回（同じ親ID＋繰返し基準日）の他の子タスク全体を平行移動する。

### 1.12 プロジェクト管理（一覧テーブル）

登録済みの全プロジェクト（配下タスク件数の多い順）を1行1件で表示する管理者向けテーブル（旧・独立した「プロジェクトタブ」の一覧機能のみを残したもの。[データ編集タブ](#3-データ編集タブ)下部のExpanderとして常駐）。

| 操作 | 内容 |
|---|---|
| 状態 | 表示中／非表示中をボタンでトグル（非表示にすると各タブのプロジェクト選択肢から除外される） |
| 名前変更 | プロジェクトのタイトルをその場で変更 |
| 統合 | このプロジェクトを他のプロジェクトへ統合する。直属の子は全て統合先の子に付け替わり、自身も統合先の子（通常タスク）に降格する。循環参照になる統合は拒否 |
| 削除 | 直属の子がある場合、削除確認時に「別プロジェクトへ付け替え」または「未割り当て（単独タスク）にする」を選んでから削除 |

### 1.13 タスク一覧

画面下部に常時表示。現在のフィルタ適用済みの全タスク（データ区分・日付を問わず全件）を表形式（チェックボックス／ID／データ区分／タイトル／ステータス／親ID／開始予定／終了予定／完了日）で一覧表示し、行クリックで編集対象を切り替える。チェックボックスは[PJ一括編集](#17-プロジェクトツリー表示)の複数選択対象。

## 2. INBOXタブ

思いついたことをその場でとりあえず登録する、最も単純な入力画面。DOM上のIDプレフィックスは `inbox-`。

- テキストエリアに内容を入力し「登録」ボタンでデータ区分「INBOX」として即座に1件保存する。
- タイトルは入力内容の先頭15文字を自動採番。IDは既存の最大ID+1で自動採番。
- 登録時のカテゴリは、画面上部で選択中のカテゴリ（「すべて」の場合は空欄）を自動設定。
- 登録後はGitHubへの送信を待たずLocalStorageに即時保存される（[添付C](#c-データ読み書きオフライン対応)参照）。
- 登録された行は、後から[データ編集タブ](#3-データ編集タブ)でタスク／ナレッジへ振り分ける想定。

## 3. データ編集タブ

INBOX／タスク／ナレッジを横断して一覧・検索・一括編集・データ区分変更ができる統合編集画面と、メインデータ・マスタデータの生の内容を直接編集できるテーブル（旧・独立した「データタブ」）を統合したページ。DOM上のIDプレフィックスは `edit2-`／`table-main`・`table-master`。

### 3.1 データ区分タブ

- マスタに登録済みのデータ区分（INBOX／タスク／ナレッジ等）をラジオタブとして表示し、件数バッジ付きで一覧を絞り込む。

### 3.2 フィルタ

- 共通：タグ／プロジェクト（親ID方式）／作成日時範囲／更新日時範囲。
- タスク区分選択時：優先度／開始予定範囲／終了予定範囲／ステータス。
- ナレッジ区分選択時：Input／PARA区分／ステータス。

### 3.3 一覧テーブル

- フィルタ適用済みの一覧をチェックボックス付きテーブルで表示し、複数行を選択できる（一括編集の対象になる）。

### 3.4 入力・編集フォーム

- 1件選択時：その行の内容がフォームに自動入力される（複数選択時はタイトル・内容・備考は空欄のまま、他項目は共通適用値として扱う）。
- 「移動先のデータ区分」を切り替えると、タスク／ナレッジ固有の項目（優先度・開始予定・終了予定・見積時間 / Input・Output・PARA区分）の表示が切り替わる。
- 親（プロジェクト）はID・タイトル検索で紐付け（複数選択時は親IDの一括変更は不可、1件選択時のみ）。

### 3.5 操作ボタン

- **新規**：選択状態に関わらず、フォームの現在値で新規データを1件追加。
- **更新**：選択中の行（複数可）へフォームの入力値をまとめて適用する一括更新。値が空欄の項目は変更しない（既存値を保持）。データ区分は選択行全件に強制適用される。
- **削除**：選択中の行（複数可）を完全に削除。削除された行を親としていた子行は親ID欄を空欄化する。

### 3.6 メインデータ一覧／マスタデータ一覧

編集フォームの下部、Expanderとして常駐（旧・独立した「データタブ」の内容をそのまま移植）。

- **メインデータ一覧**：現在のカテゴリフィルタ適用済みの全メインデータ行を、`MAIN_DATA_COLUMNS`（[dataModel.js](./js/modules/dataModel.js)で定義）の全列でテーブル表示。セルは直接クリックして編集可能（ID列のみ編集不可）。編集確定（フォーカスアウト）で即座にLocalStorageへ保存。「行を追加」ボタンで空行を1件追加。
- **マスタデータ一覧**：カテゴリ・タグ・プロジェクト・ステータス等の親子関係定義（`MASTER_DATA_COLUMNS`）を同様にテーブル編集。編集のたびに整合性チェック（`master.js`）を再実行し、問題があれば[添付A](#a-上部バーsummaryページ最上部全タブ共通)の警告バナーに反映する。同じく[1.12 プロジェクト管理](#112-プロジェクト管理一覧テーブル)もこの直下に常駐する。「行を追加」ボタンで空行を1件追加。

## 4. ナレッジタブ

登録済みの「ナレッジ」区分データを、更新日時の新しい順に一覧表示する画面。DOM上のID `knowledge-list-summary`（一覧）／`knowledge-detail-summary`（詳細パネル）。

- 表示列：タイトル／ステータス／カテゴリ／タグ／更新日時。
- 編集は[データ編集タブ](#3-データ編集タブ)から行う（一覧・詳細パネルからの直接編集は不可）。

### 4.1 詳細パネル（Zettelkasten型リンク表示）

一覧の行をクリックすると、下に選択中ノートの詳細パネルを表示する。

| 項目 | 内容 |
|---|---|
| 基本情報 | タイトル／ステータス／カテゴリ／タグ／PARA区分 |
| 所属プロジェクト | `親ID` が設定されていれば親行のタイトルを表示（親IDが存在しない場合は「不明な親 #ID」） |
| 本文 | `内容`／`備考` を表示。本文中の `[[ID]]` 記法を自動でリンクチップに変換し、クリックでそのノートの詳細パネルへ切り替わる。リンク先IDが存在しない場合は「不明なノート #ID」として非活性表示 |
| バックリンク | 選択中ノートを `[[ID]]` で参照している他の行（データ区分を問わず全件）を一覧表示。クリックでそのノートへ切り替わる |

- リンクは`js/modules/zettel.js`の`extractLinkIds`／`findBacklinks`で解決する。リンクは手書きの`[[ID]]`記法のみ対応（タイトルでの解決や挿入補助UIは無し）。
- リンク・バックリンクの対象は「データ区分＝ナレッジ」に限らず、`内容`／`備考`に`[[ID]]`が書かれていれば任意の行（タスク等）を参照・被参照できる。

### 4.2 PARA×Zettelkastenの運用方針

既存の`PARA区分`列・マスタ値（期限知識／継続知識／関心資料／アーカイブ等）はそのまま残しつつ、実運用は以下の役割分担に寄せていく方針。

- **P（Projects）**: 「親ID」によるプロジェクト階層（[1.7](#17-プロジェクトツリー表示)・[1.12](#112-プロジェクト管理一覧テーブル)）にそのまま乗せる。プロジェクトは完了してもProjectのまま扱い、独立した「アーカイブ」状態への移行は行わない（進行状況は`ステータス`列で判断する）。
- **A（Areas）／R（Resources）**: 本章4.1のZettelkasten型リンク（`[[ID]]`・バックリンク）で自由に連結して管理する。
- **A（Archive）**: 上記2つとは別に、AR（Zettelkastenノート）側で「不要になったもの」を明示的にアーカイブする仕組みを想定しているが、現時点では未実装（方向性の合意のみ）。将来的にはステータスマスタへの「アーカイブ」追加＋ナレッジ一覧からの既定除外フィルタなどを検討。

### 4.3 専用ビューア

タグ別の専用UI。カテゴリが一致するものだけボタンを表示する（既定は折りたたみ）。

#### 4.3.1 料理レシピ

タグ＝料理のナレッジ行を専用フォームで一覧・編集する（`入力`／`実践`の2モード切替）。

- **入力モード**：レシピの新規登録・編集。料理名・カテゴリ・ステータスに加え、ステータスが「一時メモ」なら自由記述のメモ欄、「永久保存」なら構造化フォーム（想定人数／材料／前処理／作り方／改善点。材料・前処理・作り方はそれぞれ表形式で行を追加・削除できる）を表示する。
- **実践モード**：永久保存レシピを複数選択し、調理中に見やすく表示する。「タブ切替」「並列表示」のレイアウトを選べる。

#### 4.3.2 読書メモ

タグ＝読書のナレッジ行を、本→章メモ→QAカードの親ID階層で専用フォームで一覧・編集する。

- **本**：書名・カテゴリ・ステータス・本全体のメモを管理。
- **章メモ**（本を選択した場合のみ表示）：章タイトル・ステータス・PARA区分・内容（章のメモ本文）を管理。
- **QAカード**（章メモを選択した場合のみ表示）：一問一答形式の問題・答えを管理。「暗記モードを開始」ボタンで出題（シャッフル）→答えを見る→次へ、の暗記モードを実行できる。

## 共通機能・添付資料

### A. 上部バー（Summaryページ最上部、全タブ共通）

| 要素 | 内容 |
|---|---|
| 警告バナー | マスタデータの整合性チェック（`master.js`の`computeMasterWarnings`）で問題が検出された場合、ページ最上部に赤字で表示 |
| カテゴリ選択 | マスタの `(M)カテゴリ` 列から一意に抽出したカテゴリのラジオ選択。「すべて」を含む。選択中カテゴリは全タブのフィルタ・一覧・新規登録の初期値に影響する |
| 読込／保存 | 「読込」：GitHubから最新データを取得。「保存」：現在のデータをGitHubへ保存（詳細は[C](#c-データ読み書きオフライン対応)） |
| 出力／入力 | Excel（.xlsx）としてエクスポート／インポート（`excel.js`） |
| トークン入力 | GitHub Personal Access Token（`github_pat_...`）をパスワード欄に入力。読込・保存・[Info](#5-info)のREADME取得に共通で使う単一トークン（`brain_data`・`brain`の両リポジトリに対する権限が必要）。読込・保存・Excel出力・Excel入力のいずれかを実行するたびに、その時点の入力値をLocalStorageへ保存する |
| 同期ステータス表示 | オンライン（最新）／オフライン（未同期）等のバッジ表示 |
| キャッシュ更新 | スマホ等でのPWAキャッシュが古いままの場合に、キャッシュバスター付きURLで強制リロードする |

### B. データモデル

- **mainData**：日々のタスク・ナレッジ・INBOX等（列定義は`dataModel.js`の`MAIN_DATA_COLUMNS`）。
- **masterData**：カテゴリ・タグ・プロジェクト・ステータス等の親子関係定義（`MASTER_DATA_COLUMNS`）。
- 親子関係（プロジェクト所属・繰返し親子）はすべて「親ID」列（`親ID`）1本の親ID方式で表現する。旧・フラット文字列の「プロジェクト」列は完全に廃止済み（[添付G](#g-構成変更履歴)参照）。

### C. データ読み書き・オフライン対応

- 読み込み：GitHub API → 成功時はテキスト＋SHAをLocalStorageにキャッシュ。失敗時はキャッシュから復元。
- 保存：ボタン押下で即座にLocalStorage更新 → GitHubへPUT送信。圏外失敗時もデータはローカルに保持され、ユーザーに通知。
- 自動保存：1分ごとに、トークン設定済み・データ読込済みかつ変更がある場合のみ自動的にGitHubへ保存（アラート等は出さない）。
- 保存競合（409）時：mainDataはID単位の3-wayマージ（`merge.js`）で自動解決、masterDataは片方のみ変更ならそちらを自動採用、両方変更されていた場合のみユーザーに選択を求める。

### D. タイムスタンプログ形式・実績時間の計算

- タイマー開始時：`YYYY/MM/DD HH:mm:ss-` を末尾に追記。
- タイマー停止時：`YYYY/MM/DD HH:mm:ss, ` を末尾に追記（開始と停止のペアで1区間）。
- 計測中判定：ログ末尾が `-` で終わっている状態。
- 実績時間は、ログ中の全区間の合計＋「補正時間」欄の値（分、正負可）で算出する。

### E. 1日タスク（DAYPLAN）の共通仕様

- [1.8](#18-日別タイムライン1日タスクdayplan)から同一のデータ（データ区分＝ナレッジ・PARA区分＝1日タスクの特殊行、日付ごとに1件）を参照・編集する。ナレッジタブの一覧からは除外される。
- 内容欄に「`[列番号] HH:MM-HH:MM 内容`」または「`[列番号] HH:MM-HH:MM #ID ラベル`」の行を1行1件書式で保持し、`#ID`があれば既存タスクへのリンクとして扱う。先頭の`[列番号]`（1〜4）は省略可能で、省略された行（旧データ・1日タスクに未追加のタスクの表示など）は重なりに応じてどこかの列へ自動的に詰め込んで表示する（表示用のフォールバックであり、内容テキストは書き換わらない）。
- 列1は「開始予定・終了予定が既に時刻まで決まっているタスク」の定位置で、重なりを気にせずそのまま配置する。列2〜4は時間未定タスクの作業枠で、ドラッグ等で時間が重なった場合は自動的に押し出して重ならないよう調整する（詳細は[1.8](#18-日別タイムライン1日タスクdayplan)）。

### F. 日付・データ形式の表記ゆれ

- 日時は基本的に `YYYY/MM/DD HH:mm:ss`（スラッシュ区切り）で保持し、`<input type="date">` とやり取りする際のみ `YYYY-MM-DD`（ハイフン区切り）に変換する。
