## 1. 繰返しタブ

定期的に発生するタスク（親タスク＝繰返しテンプレート）を1件登録しておくと、実行日ごとに実際のタスク（子タスク）を都度手動生成して管理できる機能。DOM上のIDプレフィックスは `recurring-` / `recuredit-`。子タスクの親IDは繰返しテンプレート自身のIDを指す（＝親ID方式の階層に組み込まれる）。繰返しテンプレートは`繰返し識別子`列で判定し、通常のプロジェクト一覧・PJ(n層)ピッカーには（プロジェクト候補としては）表示されない。

### 1.1 フィルタ

- 画面上部の「フィルタ」を展開すると、タグ／プロジェクト（親ID方式）／ステータスによる複数選択フィルタを表示。
- 以降の週間ボード・タスク一覧はすべてこのフィルタが適用された親タスクを対象にする。

### 1.2 週間ボード

- 月〜日の7列で、その週に頻度条件が一致する親タスク（または既に生成済みならその子タスク）をタイトル1行で表示する。
- `‹` `›` で前後の週へ移動、「今週」ボタンで当週に戻る。
- 頻度条件の判定は親タスクの「繰返し頻度_月／日／曜日」（カンマ区切り、AND条件、すべて空欄なら毎日該当）。
- 開始予定に時刻が入力されている親タスクは時刻の早い順に並ぶ。
- 行をクリックすると右側の「編集」パネルに読み込まれる。

### 1.3 タスク一覧（実行／編集の2タブ）

- **実行タブ**（既定表示）: 当日の頻度条件に一致する親タスクを開始予定順に表示。
  - まだ当日分の子タスクが未生成の親タスクは「＋」ボタンで子タスクを「進行中」ステータスとして生成できる。
  - 既に生成済みの子タスクは、タイトル行の右に以下の操作ボタンを表示する：
    - `▷`／`□`：タイマー開始／停止（打刻はタイムスタンプログに追記、実行中は開始ボタンを無効化）
    - `完了`：完了日・ステータスを更新（完了済みは緑色表示になり▷/□は非表示）
- **編集タブ**: フィルタ適用済みの全親タスクをタイトルのみ一覧表示（＋やタイマー操作は無し）。選択すると右側に子タスク一覧を追加表示する。
- 「新規追加」ボタンで新規の親タスク登録モードに切り替え。
- 「実行タスク生成」ボタン＋日付指定：任意の日付を基準日として、選択中の親タスクから子タスクを手動生成できる（頻度条件はチェックしない）。

### 1.4 実績グラフ

- 選択中の親タスクの子タスク実績（完了日 or 作成日時 × 実績時間）を折れ線／棒グラフで可視化（Chart.js使用）。
- 既定は非表示。「グラフ」ボタンで表示切り替え。

### 1.5 編集フォーム（親タスク・子タスク共通）

親タスク・子タスクいずれを選択した場合も同じフォームを使うが、一部の項目は親タスク選択時のみ表示される。

| 項目 | 内容 |
|---|---|
| ID / タイトル / 内容 / 備考 | 基本情報。備考欄は親タスクの場合「子タスクテンプレート」の入力に使われるため、編集フォーム上には表示されない |
| ステータス / 優先度 / 見積時間（分） / 実績時間（分、読取専用） | 通常のタスク属性 |
| 頻度（月・日・曜日） | **親タスクのみ表示**。チップ形式で複数選択。空欄=全て対象（AND条件） |
| 子タスクテンプレート | **親タスクのみ表示**。1回の生成で複数の子タスクを作成できるようテンプレートを複数登録可能（オフセット日数・タイトル接尾辞・内容を指定）。実体は備考欄にJSON文字列として保存される |
| 開始予定・終了予定・完了日 | 日付＋時刻（時／分） |
| カテゴリ・タグ | マスタ選択式 |
| 親（プロジェクト） | ID・タイトルで検索して紐付け |

#### 1.5.1 子タスクテンプレートの生成仕様

- テンプレートは `{ offsetDays, titleSuffix, content }` の配列。
- 生成基準日から最も早いオフセット日を「開始予定」として全テンプレート共通で使用し、「終了予定」は各テンプレート自身のオフセット日を使用する。
- 同一親ID・同一基準日・同一タイトルの子タスクが既に存在する場合は再生成しない（重複防止）。
- 未設定の場合は「オフセット0、当日1件のみ生成」という従来動作にフォールバックする。

#### 1.5.2 編集フォームの操作ボタン

- **新規**：新規親タスク登録モードにリセット。
- **適用**：選択中タスクの変更を保存。
- **グループに適用**（子タスク選択時のみ表示）：開始予定・終了予定の変更差分（両方変更時は開始予定側優先）を日数差分として算出し、同じ回（同じ親ID＋繰返し基準日）の他の子タスク全体を平行移動する。
- **完了にする**：開始予定・終了予定・完了日を本日にし、ステータスを完了にして保存。
- **削除**：選択中タスク（親または子）を削除。

## 2. タスク整理タブ

タスク・ナレッジの親子関係を「親ID」1本で表現する整理画面。任意の階層でタスク／ナレッジを親子に紐付けられる。DOM上のIDプレフィックスは `taskorg2-` / `calendar2-` / `dayedit2-`。

### 2.1 フィルタ

- 表示順は「タグ」→「ステータス」→「プロジェクト」（いずれも複数選択）。プロジェクトは親子ツリーの最上位（ルート）を1つの単位として集計・フィルタする。
- その下に「その他フィルタ」として、カレンダー・タスクリストへの表示有無を切り替えるチェックボックスを3つ配置：
  - **プロジェクト**：プロジェクト（親）行自体を表示するかどうか（既定OFF）
  - **繰返し親タスク**：繰返しタスクの親（テンプレート）行を表示するかどうか（既定OFF）
  - **繰返し子タスク**：繰返しタスクから生成された子タスクを表示するかどうか（既定ON）

### 2.2 カレンダー／ガントチャートの切り替え

- 「カレンダー」「ガントチャート」の2ビューをタブ切替（表示中の年月は共有）。
- **カレンダービュー**：月間グリッド。日をクリックするとその日を選択し、下部の日別タイムラインに反映する（選択中タスクは解除される）。
- **ガントチャートビュー**：表示単位「日」「週」を切替可能。ステータス別配色（未着手／進行中／中断等／完了）の凡例付き。勤務カレンダーの例外設定（休日等）も反映される。

### 2.3 日別タイムライン（選択日の1日の予定）

- 0:00〜24:00を縦軸にしたタイムラインに、選択日の「開始予定・終了予定に時刻が入力されているタスク」をブロック表示（複数重なる場合はレーン分割）。
- 未確定タスクや、1日タスクのブロックとして参照済みのタスクは通常枠に出さず、下部の「未設定/設定済みタスク」側に振り分ける。
- ブロックはドラッグで移動・端のハンドルでリサイズ可能（15分単位にスナップ）。ドラッグ確定でタスクの開始予定・終了予定（1日タスクのブロックならその行の時刻情報）を書き換えて保存する。
- ブロッククリック（移動量が閾値未満の場合）で編集対象として選択される。

### 2.4 1日タスク（DAYPLAN）

- 選択日ごとに1件、その日のスケジュールを「HH:MM-HH:MM 内容」または「HH:MM-HH:MM #ID ラベル」形式のテキストで管理する特殊行（データ区分＝ナレッジ・PARA区分＝1日タスク固定。作業ログ的な性質のためタスクではなくナレッジとして管理する）。
- 未作成の日は「1日タスクを作成」ボタンで新規作成。作成時、その日既に時刻指定済みの既存タスクを自動的に取り込んでブロック化する（既定は「09:00-09:30 メールチェック、予定整理」を含む）。
- 「保存」でテキスト内容を反映、「1日タスクを削除」でその日の1日タスク自体を削除。
- タブを開いた時点では常に「今日」が選択された状態になる（1日タスクも今日の分が対象）。

### 2.5 未設定／設定済みタスクなどの一覧（既定は折りたたみ）

いずれも現在のフィルタ・カテゴリ適用後の一覧をチップ形式で表示し、クリックで編集対象に選択できる。

| 折りたたみ項目 | 内容 |
|---|---|
| 未設定/設定済みタスク | 選択日について、未設定（時間帯未定）タスクと、1日タスクに追加済み（参照済み）のタスクを分けて表示 |
| 日付未確定のタスク | 開始予定・終了予定のいずれかが空欄のタスク |
| 属性未設定タスク | カテゴリ／ステータス／優先度／プロジェクト（親ID未設定）のいずれかが未入力のタスクを領域別に表示（重複表示あり） |
| 中断タスク | ステータスが「中断」のタスク |

### 2.6 編集フォーム（新規登録・既存タスク編集共通）

| 項目 | 内容 |
|---|---|
| ID / タイトル / 内容 / 備考 | 基本情報 |
| ステータス | ステータス選択。「完了」に変更すると完了日を自動的に本日にする |
| 繰り返し（チェックボックス） | オンにすると、このタスクを繰返しタスクの親として扱い、頻度（月・日・曜日）の入力欄を表示する。頻度の仕様は[繰返しタブ1.5](#1-繰返しタブ)と共通 |
| 優先度 / 見積時間（分） / 実績時間（分、読取専用） | 通常のタスク属性 |
| 開始予定・終了予定・完了日 | 日付＋時刻（時／分）。開始時刻を入力すると終了予定を1時間後に自動補完（手動修正可）。「開始/終了に反映」ボタンで完了日の値を開始・終了予定にコピーできる |
| カテゴリ・タグ | マスタ選択式 |
| 親（プロジェクト） | ID・タイトルで検索して任意の階層に紐付け（「解除」で親なしに戻せる） |

- 「新規登録」ボタンでフォームをリセットし新規登録モードへ（この場合のみ日付を空欄のままにする。それ以外はカレンダーで選択中の日付を初期値にする）。
- 「新規」／「適用」／「削除」ボタンで登録・更新・削除。保存後はタスク実行タブ・繰返しタブの表示も追従する。

### 2.7 配下（子）タスク／ナレッジ一覧

- 選択中の行に「親ID」で紐付く子タスク・ナレッジを読み取り専用の一覧として表示。

### 2.8 タスク一覧

- 画面下部に常時表示。現在のフィルタ適用済みの全タスク（データ区分＝タスク、日付を問わず全件）を表形式（ID／データ区分／タイトル／ステータス／親ID／開始予定／終了予定／完了日）で一覧表示し、行クリックで編集対象を切り替える。

## 3. タスク実行タブ

「今この瞬間に何をするか」に特化した実行専用画面。左側に4種類のタスク一覧、右側に選択中タスクの実行用パネルを表示する2カラム構成。DOM上のIDプレフィックスは `runner-`。

### 3.1 タスク一覧（左カラム、4種のテーブル）

| 一覧 | 対象 |
|---|---|
| 進行中（今日） | ステータス「進行中」かつ、今日の1日タスクに `#ID` で明示的に組み込まれているタスク |
| 進行中（今日以外） | ステータス「進行中」だが、今日の1日タスクには含まれていないタスク |
| その他（今日） | 今日の1日タスクに含まれるが「進行中」ではないタスク。「進行中にする」ボタンでステータスを進行中に変更できる |
| （親タスク） | 進行中タスクのうち、他タスクの親（プロジェクト）になっているもの |

- 「進行中」系の一覧には行ごとに `▷`（タイマー開始）／`■`（タイマー停止）／`完了`ボタンを表示。
- タイマー開始時、既に別のタスクが計測中であれば自動的にそちらを停止してから新しいタスクを開始する（同時に複数のタイマーは走らない）。
- 行タイトルのクリックで右側の実行パネルに読み込む。

### 3.2 実行パネル（右カラム）

- 選択中タスクのタイトル・累計時間（タイムスタンプログから算出、計測中は1秒ごとにライブ更新）を表示。
- 「補正」欄：分単位で累計時間を加減算する補正値を入力できる。
- タイムスタンプログをテキストエリアで直接編集可能。
- カテゴリ・タグ・優先度等の属性編集欄（共通の属性編集UIを使用。プロジェクトはタスク整理と同じ親ID方式のPJ(n層)階層プルダウンで紐付け、「＋ 新規PJを追加」でその場に新規プロジェクトを作成可能）。
- 「ステータス遷移」：開始・停止・完了以外のステータス（マスタ登録済みのタスク用ステータス）にラジオボタンで変更できる。
- 選択中タスクが無ければ、進行中（今日）→進行中（今日以外）→その他（今日）→親タスクの順で自動的に先頭タスクを選択する。

## 4. INBOXタブ

思いついたことをその場でとりあえず登録する、最も単純な入力画面。DOM上のIDプレフィックスは `inbox-`。

- テキストエリアに内容を入力し「登録」ボタンでデータ区分「INBOX」として即座に1件保存する。
- タイトルは入力内容の先頭15文字を自動採番。IDは既存の最大ID+1で自動採番。
- 登録時のカテゴリは、画面上部で選択中のカテゴリ（「すべて」の場合は空欄）を自動設定。
- 登録後はGitHubへの送信を待たずLocalStorageに即時保存される（[共通機能](#共通機能添付資料)参照）。
- 登録された行は、後から[編集タブ](#5-編集タブ)でタスク／ナレッジへ振り分ける想定。

## 5. 編集タブ

INBOX／タスク／ナレッジを横断して一覧・検索・一括編集・データ区分変更ができる統合編集画面。データ区分をまたいだ振り分け作業（INBOX→タスク化など）を主目的とする。DOM上のIDプレフィックスは `edit2-`。

### 5.1 データ区分タブ

- マスタに登録済みのデータ区分（INBOX／タスク／ナレッジ等）をラジオタブとして表示し、件数バッジ付きで一覧を絞り込む。

### 5.2 フィルタ

- 共通：タグ／プロジェクト（親ID方式）／作成日時範囲／更新日時範囲。
- タスク区分選択時：優先度／開始予定範囲／終了予定範囲／ステータス。
- ナレッジ区分選択時：Input／PARA区分／ステータス。

### 5.3 一覧テーブル

- フィルタ適用済みの一覧をチェックボックス付きテーブルで表示し、複数行を選択できる（一括編集の対象になる）。

### 5.4 入力・編集フォーム

- 1件選択時：その行の内容がフォームに自動入力される（複数選択時はタイトル・内容・備考は空欄のまま、他項目は共通適用値として扱う）。
- 「移動先のデータ区分」を切り替えると、タスク／ナレッジ固有の項目（優先度・開始予定・終了予定・見積時間 / Input・Output・PARA区分）の表示が切り替わる。
- 親（プロジェクト）はID・タイトル検索で紐付け（複数選択時は親IDの一括変更は不可、1件選択時のみ）。

### 5.5 操作ボタン

- **新規**：選択状態に関わらず、フォームの現在値で新規データを1件追加。
- **更新**：選択中の行（複数可）へフォームの入力値をまとめて適用する一括更新。値が空欄の項目は変更しない（既存値を保持）。データ区分は選択行全件に強制適用される。
- **削除**：選択中の行（複数可）を完全に削除。削除された行を親としていた子行は親ID欄を空欄化する。

## 6. ナレッジタブ

登録済みの「ナレッジ」区分データを、更新日時の新しい順に一覧表示する画面。DOM上のID `knowledge-list-summary`（一覧）／`knowledge-detail-summary`（詳細パネル）。

- 表示列：タイトル／ステータス／カテゴリ／タグ／更新日時。
- 編集は[編集タブ](#5-編集タブ)から行う（一覧・詳細パネルからの直接編集は不可）。

### 6.1 詳細パネル（Zettelkasten型リンク表示）

一覧の行をクリックすると、下に選択中ノートの詳細パネルを表示する。

| 項目 | 内容 |
|---|---|
| 基本情報 | タイトル／ステータス／カテゴリ／タグ／PARA区分 |
| 所属プロジェクト | `親ID` が設定されていれば親行のタイトルを表示（親IDが存在しない場合は「不明な親 #ID」） |
| 本文 | `内容`／`備考` を表示。本文中の `[[ID]]` 記法を自動でリンクチップに変換し、クリックでそのノートの詳細パネルへ切り替わる。リンク先IDが存在しない場合は「不明なノート #ID」として非活性表示 |
| バックリンク | 選択中ノートを `[[ID]]` で参照している他の行（データ区分を問わず全件）を一覧表示。クリックでそのノートへ切り替わる |

- リンクは`js/modules/zettel.js`の`extractLinkIds`／`findBacklinks`で解決する。リンクは手書きの`[[ID]]`記法のみ対応（タイトルでの解決や挿入補助UIは無し）。
- リンク・バックリンクの対象は「データ区分＝ナレッジ」に限らず、`内容`／`備考`に`[[ID]]`が書かれていれば任意の行（タスク等）を参照・被参照できる。

### 6.2 PARA×Zettelkastenの運用方針

既存の`PARA区分`列・マスタ値（期限知識／継続知識／関心資料／アーカイブ等）はそのまま残しつつ、実運用は以下の役割分担に寄せていく方針。

- **P（Projects）**: 既存の「親ID」によるプロジェクト階層（[プロジェクトタブ](#7-プロジェクトタブ)）にそのまま乗せる。プロジェクトは完了してもProjectのまま扱い、独立した「アーカイブ」状態への移行は行わない（進行状況は`ステータス`列で判断する）。
- **A（Areas）／R（Resources）**: 本章6.1のZettelkasten型リンク（`[[ID]]`・バックリンク）で自由に連結して管理する。
- **A（Archive）**: 上記2つとは別に、AR（Zettelkastenノート）側で「不要になったもの」を明示的にアーカイブする仕組みを想定しているが、現時点では未実装（方向性の合意のみ）。将来的にはステータスマスタへの「アーカイブ」追加＋ナレッジ一覧からの既定除外フィルタなどを検討。

## 7. プロジェクトタブ

プロジェクト（親子ツリーの管理単位）を一覧管理・階層編集するための画面。「親ID」で表現された階層構造を、ブラウザ形式のプルダウンで掘り下げながら編集する。DOM上のIDプレフィックスは `project2-` / `projtask2-`。

### 7.1 プロジェクト管理（一覧テーブル）

登録済みの全プロジェクト（配下タスク件数の多い順）を1行1件で表示し、行ごとに以下の操作を行える。

| 操作 | 内容 |
|---|---|
| 状態 | 表示中／非表示中をボタンでトグル（非表示にすると各タブのプロジェクト選択肢から除外される） |
| 名前変更 | プロジェクトのタイトルをその場で変更 |
| 統合 | このプロジェクトを他のプロジェクトへ統合する。直属の子は全て統合先の子に付け替わり、自身も統合先の子（通常タスク）に降格する。循環参照になる統合は拒否 |
| 削除 | 直属の子がある場合、削除確認時に「別プロジェクトへ付け替え」または「未割り当て（単独タスク）にする」を選んでから削除 |

### 7.2 階層プルダウン＋下階層の一覧（左カラム）

- 選択済みの階層だけプルダウンを積み上げて表示し、選択するたびに1段深い階層のプルダウンが追加される（親IDをたどるパンくず的な操作）。
- 「下階層の一覧」：現在選択中の階層の直属の子を一覧表示。
- 「階層整理」：現在選択中の階層と同じ親を持つ兄弟行をチェックボックスで複数選択し、「選択した兄弟をこの下へ移動」ボタンで選択中の階層の子へまとめて付け替える（循環参照チェックあり）。

### 7.3 編集（右カラム）

| 項目 | 内容 |
|---|---|
| ID / データ区分 / タイトル / 内容 / 備考 | 基本情報。データ区分はタスク／ナレッジ等から選択 |
| ステータス / 優先度 / 見積時間（分） / 実績時間（h、読取専用） | 通常のタスク属性 |
| 開始予定・終了予定・完了日 | 日付＋時刻（時／分） |
| カテゴリ・タグ | マスタ選択式 |
| 上階層 | ID・タイトル検索で親を紐付け（「解除」で最上位に戻せる） |

- **上階層を挿入**：選択中の行と、その元の親との間に新しい階層（新規行）を1件挿入する。
- **下階層に追加**：フォームの内容で、選択中の行の子として新規行を追加。
- **適用**／**削除**：選択中の行を更新／削除。
- **新規プロジェクト登録**：フォームのタイトル・カテゴリを使い、独立した新規プロジェクト（親を持たないタスク）を登録する。

## 8. データタブ

メインデータ・マスタデータの生の内容を直接確認・編集できる画面（トラブル対応や一括修正向け）。DOM上のID `table-main` / `table-master`。

### 8.1 メインデータ一覧

- 現在のカテゴリフィルタ適用済みの全メインデータ行を、`MAIN_DATA_COLUMNS`（[dataModel.js](./js/modules/dataModel.js)で定義）の全列でテーブル表示。
- セルは直接クリックして編集可能（ID列のみ編集不可）。編集確定（フォーカスアウト）で即座にLocalStorageへ保存。
- 「行を追加」ボタンで空行を1件追加。

### 8.2 マスタデータ一覧

- カテゴリ・タグ・プロジェクト・ステータス等の親子関係定義（`MASTER_DATA_COLUMNS`）を同様にテーブル編集。
- 編集のたびに整合性チェック（`master.js`）を再実行し、画面上部に警告バナーを表示する。
- 「行を追加」ボタンで空行を1件追加。

## 9. 勤務タブ

出勤日・休日・有給・特別休暇などの勤務区分をカレンダー形式で管理する画面。タスク整理のガントチャートの非稼働日表示にも利用される。DOM上のIDプレフィックスは `work-cal-`。

### 9.1 年月ナビゲーション・カレンダーグリッド

- 年・月それぞれに `‹` `›` ボタンで移動。
- 月間グリッドに、その日の勤務区分（既定の曜日パターン、または個別の例外設定があればそちらを優先）を色分け表示。例外設定がある日は専用マークを表示。

### 9.2 月次サマリー

- 表示中の月について、区分ごとの日数を集計表示。

### 9.3 月一括編集フォーム

- 1日1行のテーブルで、種別（デフォルトのまま／出勤日／休日／有給／特別休暇）と備考を入力。
- 「月一括適用」ボタンで、表示中の月の例外設定をまとめて保存（種別が「デフォルトのまま」の行は例外設定から除外＝既定の曜日パターンに戻る）。

## 共通機能・添付資料

### A. 上部バー（Summaryページ最上部、全タブ共通）

| 要素 | 内容 |
|---|---|
| カテゴリ選択 | マスタの `(M)カテゴリ` 列から一意に抽出したカテゴリのラジオ選択。「すべて」を含む。選択中カテゴリは全タブのフィルタ・一覧・新規登録の初期値に影響する |
| 読込／保存 | 「読込」：GitHubから最新データを取得。「保存」：現在のデータをGitHubへ保存（詳細は[C](#c-データ読み書きオフライン対応)） |
| 出力／入力 | Excel（.xlsx）としてエクスポート／インポート（`excel.js`） |
| トークン入力 | GitHub Personal Access Token（`github_pat_...`）をパスワード欄に入力。読込・保存に必須 |
| 同期ステータス表示 | オンライン（最新）／オフライン（未同期）等のバッジ表示 |
| キャッシュ更新 | スマホ等でのPWAキャッシュが古いままの場合に、キャッシュバスター付きURLで強制リロードする |

### B. データモデル

- **mainData**：日々のタスク・ナレッジ・INBOX等（列定義は`dataModel.js`の`MAIN_DATA_COLUMNS`）。
- **masterData**：カテゴリ・タグ・プロジェクト・ステータス等の親子関係定義（`MASTER_DATA_COLUMNS`）。
- 親子関係の表現方式は画面によって異なる：
  - **プロジェクト名方式**（タスク実行タブの実行パネル）：`プロジェクト`列にマスタ登録済みの文字列を設定
  - **親ID方式**（タスク整理・繰返し・編集タブ・プロジェクトタブ）：`親ID`列に親行のID（数値文字列）を設定し、任意の深さの階層を組める

### C. データ読み書き・オフライン対応

- 読み込み：GitHub API → 成功時はテキスト＋SHAをLocalStorageにキャッシュ。失敗時はキャッシュから復元。
- 保存：ボタン押下で即座にLocalStorage更新 → GitHubへPUT送信。圏外失敗時もデータはローカルに保持され、ユーザーに通知。
- 自動保存：1分ごとに、トークン設定済み・データ読込済みかつ変更がある場合のみ自動的にGitHubへ保存（アラート等は出さない）。
- 保存競合（409）時：mainDataはID単位の3-wayマージ（`merge.js`）で自動解決、masterDataは片方のみ変更ならそちらを自動採用、両方変更されていた場合のみユーザーに選択を求める。

### D. タイムスタンプログ形式・実績時間の計算

- タイマー開始時：`YYYY/MM/DD HH:mm:ss-` を末尾に追記。
- タイマー停止時：`YYYY/MM/DD HH:mm:ss, ` を末尾に追記（開始と停止のペアで1区間）。
- 計測中判定：ログ末尾が `-` で終わっている状態。
- 実績時間は、ログ中の全区間の合計＋「補正時間」欄の値（分、正負可）で算出する。

### E. 1日タスク（DAYPLAN）の共通仕様

- タスク整理・タスク実行タブなどから同一のデータ（データ区分＝ナレッジ・PARA区分＝1日タスクの特殊行、日付ごとに1件）を参照・編集する。ナレッジタブの一覧からは除外される。
- 内容欄に「HH:MM-HH:MM 内容」または「HH:MM-HH:MM #ID ラベル」の行を1行1件書式で保持し、`#ID`があれば既存タスクへのリンクとして扱う。

### F. 日付・データ形式の表記ゆれ

- 日時は基本的に `YYYY/MM/DD HH:mm:ss`（スラッシュ区切り）で保持し、`<input type="date">` とやり取りする際のみ `YYYY-MM-DD`（ハイフン区切り）に変換する。
